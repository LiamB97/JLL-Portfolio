# Main-map postcode commute search

Find homes by commute sits below the map search. Visitors enter a full destination postcode, maximum journey time (5–180 minutes), travel mode (public transport, walking or cycling), arrival date and time. Times are London local time; the initial date is the next weekday and the initial arrival time is 09:00. TfL supports searches up to 28 days ahead here.

The search plans each published development to the destination postcode centre using TfL Journey Planner. It uses journey.duration, including the full itinerary rather than a sum of selected legs or a distance-based speed estimate. Public transport requests include tube, bus, DLR, Overground, Elizabeth line, national rail, tram and walking. Walking and cycling modes reject routes of the wrong type. Unsupported or failed journeys are marked unavailable and excluded without being labelled outside the time limit.

The browser sends published IDs in batches of five, with two batches at a time and a checked-home progress count. Search cancellation aborts pending client requests and ignores late responses. Failed whole batches do not apply a misleading incomplete filter. Completed search results filter the map and listings, intersecting with the existing property, featured and favourites filters. The limit can be adjusted against completed results without another route lookup. Matching pins have journey-time tooltips and listing cards have time badges. The map frames the destination and matching homes; it does not use a guessed travel radius.

POST /api/commute is public, origin checked, bounded to a 6 KB payload and at most five published IDs. Destination lookup uses the fixed Postcodes.io endpoint; route requests use the fixed TfL API, never a caller-supplied URL. No profile, property or analytics writes occur. Destination and successful route caches are bounded and in memory only, with one-hour and ten-minute lifetimes respectively. Failed journeys are retried. Netlify’s existing IP rate limit still applies. Journeys depend on TfL coverage and current schedules, so visitors should allow extra time for delays and use postcode-centre timings as guidance.

The desktop header has equal outer grid columns so the title is centred across the navigation bar. The title is hidden at mobile widths. Intermediate tablet widths use a separate controls row to prevent overlap. Icon-only desktop controls retain accessible names; mobile inputs use 16 px type to avoid Safari focus zoom.

Verification covers input validation, exact TfL mode names, total duration and modal filtering, weekend/London date handling, cache invalidation/coalescing, unconfirmed routes, no unauthorised state writes, payload/origin checks and matching thresholds. Live public transport, walking and cycling requests were checked using a sample London destination. Browser layout and device interaction checks remain unavailable with browser access disabled in Work settings.
